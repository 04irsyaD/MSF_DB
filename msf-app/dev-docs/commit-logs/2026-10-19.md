## Ringkasan

- **Batch 2 — SSRF koneksi DB (T-023, Critical, OWASP A10/A01)**:
  - Modul baru `db_url_guard.py`: whitelist driver per engine (`postgresql+psycopg2`, `mysql+pymysql`, `sqlite`), whitelist query param (`sslmode`, `charset`, `connect_timeout`), tolak host yang resolve ke IP non-publik (`ip.is_global` + multicast, termasuk IPv4-mapped IPv6, `169.254.169.254`, CGNAT `100.64/10`), tolak unix socket / multi-host.
  - Anti DNS-rebinding: koneksi dikunci ke IP hasil resolve (Postgres via `hostaddr`, MySQL via host = IP). Terverifikasi: psycopg2 konek ke `hostaddr`, bukan resolve ulang.
  - URL dirakit dengan `URL.create()` (bukan f-string), jadi password berisi `@`/`:` tidak bisa membelokkan host.
  - SQLite live nonaktif default (`ALLOW_SQLITE_CONNECTION=false`); host privat ditolak default (`ALLOW_PRIVATE_DB_HOSTS=false`). `docker-compose.yml` set keduanya `true` untuk dev lokal.
  - Error koneksi dipetakan ke kategori umum (`AUTH_FAILED`, `DB_NOT_FOUND`, `HOST_UNREACHABLE`, `HOST_NOT_ALLOWED`, dll) + field `error_code` di `DBTestConnectionResponse`. Detail mentah hanya di log.
  - `/health` menambah `features.sqlite_connection`; frontend `DbConnector.tsx` menyembunyikan opsi SQLite jika `false`.
  - `get_metadata_sync` sekarang memakai engine yang sama (guard + `connect_timeout`).
  - Test: 39 test baru di `tests/test_db_url_guard.py`; total backend **76 passed**. Frontend `tsc --noEmit` dan lint bersih.
  - Deviasi dari rencana: kategori `TIMEOUT` digabung ke `HOST_UNREACHABLE` supaya refused vs timeout tidak bisa dibedakan (anti port scanning).
